# ACU — 針灸 × PNF 3D 輔助工具

### 🔗 線上直接打開：**[https://peterhsieh1119.github.io/ACU/](https://peterhsieh1119.github.io/ACU/)**

純靜態網頁的 3D 針灸／PNF 學習輔助：在同一個解剖模型上，把 **經絡穴位 ↔ 肌肉 ↔ 血管神經 ↔ PNF 對角模式** 四層資料接在一起，任一層都能點進去、互相跳轉。

## 功能

- **真實解剖模型**：體表、**79 組肌肉**、**131 件骨骼**與**31 條血管**取自 BodyParts3D 成年男性參考解剖（CC BY 4.0）
- **3D 人體**：可旋轉、縮放，體表透明度可調；前／後／左／右／頂視角一鍵切換；骨骼、血管、神經各自獨立圖層，可隨時疊上來對照
- **十四經 361 穴齊全** ＋ 14 個常用經外奇穴，共 **375 穴**，可逐條經絡開關
- **穴位資訊**：定位、主治、刺法參考深度、特定穴屬性（原穴／絡穴／郄穴／募穴／背俞穴／八會穴／八脈交會穴…）、下方肌肉、相關 PNF 模式
- **肌肉層**：**90 條肌肉**，含起點、止點、作用與神經支配；可單獨顯示或整層透視
  （其中 79 條使用真實解剖網格，來源資料未收錄的 11 條——闊背肌、腹直肌、多裂肌、腰方肌與顏面肌群——以示意幾何表示並在面板標註）
- **血管層**：**31 條**臨床相關動脈與靜脈（真實網格），含走行與針刺注意——風池與椎動脈、人迎與總頸動脈、太淵與橈動脈、委中與膕動脈…
- **神經層**：**24 條**周邊神經（示意走行），含節段、走行、支配肌肉與針刺注意；來源資料只有中樞神經，四肢神經一律以示意管線表示並在面板標註
- **鄰近結構自動計算**：選一個穴位，除了人工整理的對應之外，程式還會算出模型上 3 公分內經過的神經與血管並標上距離（例：內關「正中神經 貼近」、三陰交「大隱靜脈 0.9 cm」）
- **PNF 模式**：**20 個模式**（上肢／下肢 D1・D2、肩胛四模式、骨盆四模式、頭頸、砍劈與上舉），含動作組成、口訣、徒手接觸、臨床應用與常用技術
- **四向連結**：穴位 ↔ 肌肉 ↔ 神經 ↔ PNF，任一方向都能點擊跳轉（肌肉的「神經支配」、神經的「支配肌肉」共用同一組 id）
- **搜尋與篩選**：可用穴名、代號、主治關鍵字（如「頭痛」）搜尋，並依部位（頭面／頸項／胸部／腹部／背腰／下肢…）篩選，3D 模型會同步只留下符合的穴位
- **手機可用**：側欄改為抽屜、資訊卡從下方彈出，觸控點選有較寬的命中範圍
- **可分享連結**：選取狀態會寫進網址，例如 [`#p=LI4`](https://peterhsieh1119.github.io/ACU/#p=LI4)（合谷）、`#m=biceps`（肱二頭肌）、`#f=UE_D2F`（上肢 D2 屈曲）、`#n=sciatic`（坐骨神經）、`#v=radial_a`（橈動脈）

## 操作

| 動作 | 效果 |
|---|---|
| 拖曳 / 滾輪 | 旋轉 / 縮放 |
| 點擊穴位、肌肉、神經或血管 | 顯示資訊並聚焦鏡頭 |
| `Esc` | 清除選取 |
| `↑` `↓` | 在目前篩選結果中切換上下一個穴位 |

## 本地執行

```bash
python -m http.server 8000
# 瀏覽器開 http://localhost:8000
```

ES module 與解剖資產都需要經 http 伺服器載入，直接雙擊 index.html 無法執行。
three.js 由 CDN 載入；網頁本身沒有建置步驟，`npm install` 只有重新產生解剖資產時才需要。

彼此的關聯由程式自動推得（`npm run validate` 會檢查參照是否都對得上），不需要另外維護對照表。

## 實作重點

**穴位座標會 retarget 到真實骨架，再貼合體表。** 資料裡的座標是依骨度分寸推算的近似值，
其參考骨架與 BodyParts3D 不一樣（肘、腕、膝、踝差 3–6 公分），直接套用會整條經絡歪掉。
`js/retarget.js` 的作法是：在兩個模型上定義語意相同的體軸節點（肩→肘→腕→掌→指尖 等等），
求出穴位落在哪一段、段內比例與相對體軸的偏移方向，再到真實模型的同一段取新起點、
依兩段夾角旋轉偏移方向，最後射線打到真實體表。經絡走行線同樣處理：長線段先細分，
每個補間點各自投影，因此經絡貼著身體跑而不是從體內穿過去。

**背部穴位用真實椎體與骨度分寸定位。** 這些穴位的定義是「第 n 椎棘突下、旁開幾寸」，
用比例映射會被真實背部的深度放大（膏肓會跑到肩胛骨外面）。資料裡直接寫 `level`（椎體）
與 `lat`（旁開寸數），程式取該節椎骨的棘突高度，再用真實骨度分寸
（肩胛骨內緣到後正中線＝3寸，換算後 1寸 ≈ 2.0 cm）算出側方距離，共 60 穴這樣定位。

**依部位限定體軸。** 胸腹的穴位在幾何上常常離手臂體軸更近（淵腋、天池、大包），
不限定就會被判給手臂、射線往內穿過整個身體打到對側。程式依穴位的 `region` 指定
可用的體軸，射線距離也上限 0.28 m，杜絕穿到身體另一側。

**分層繪製決定遮蔽關係。** 繪製順序是「骨骼 → 肌肉 → 體表深度預繪 → 體表 → 經絡線 → 穴位標記」。
體表先只寫深度不上色，再單層著色：半透明的皮膚在腋下、指縫等處有多層前向面重疊，
直接畫會重複混色而出現斑駁。深度寫入也讓身體另一側的穴位被體表擋住（前視圖不會看到背俞穴），
而體內的肌肉與骨骼仍然透出來。

**血管用真實網格，神經只能用示意走行。** BodyParts3D 的血管很完整（動脈 639 件、靜脈 404 件），
從中挑出 31 條臨床相關的打包成 `vessels.bin.gz`（287 KB，打開圖層或點到某條血管才下載）。
神經就沒這麼幸運：它的 `nervous` 系統只有腦、脊髓與眼眶內的顱神經分枝，
針灸與 PNF 真正需要的正中神經、尺神經、橈神經、坐骨神經、臂叢**一條都沒有**
（用 median／ulnar／sciatic／brachial plexus 去搜都是零筆）。
所以神經層改用走行控制點掃掠成管線，和來源資料未收錄的那 11 條肌肉同一個作法，
面板上也明確標示是示意幾何、不可用於判斷穿刺路徑。

**體內結構要壓回體表以內。** 穴位本來就在皮膚上，retarget 保留「與體軸的絕對偏移量」剛好；
但神經是體內結構，示意人體比 BodyParts3D 瘦，同樣的偏移量搬過來常常已經穿出皮膚——
坐骨神經會跑到臀部後面幾公分的空中。`makeSkinClamp` 沿「體軸 → 該點」找體表交點，
超出的就拉回體表內側 1.2 公分。只拉回、不按比例壓深：射線可能先穿過胸廓再打到三角肌，
用比例壓深會把肩部的神經吸進腋窩。

**鄰近結構一半靠人工、一半靠幾何。** `data/vessels.js` 與 `data/nerves.js` 的 `points`
是人工整理的「臨床上要一起記住的組合」（風池–椎動脈、太淵–橈動脈…），只涵蓋 143 穴；
其餘的由程式在選取當下計算：穴位到神經走行曲線的點–線段距離、到血管網格點雲的最短距離，
3 公分內的一併列出並標上距離。人工項目排前面且不標距離，幾何項目標距離，兩者在面板上分得出來。

**分階段載入，體表一到就能用。** 首次開啟只擋在體表（201 KB）：人體與 375 個穴位先畫出來，
肌肉網格（815 KB）在背景載入、到了再換掉暫時頂替的示意幾何，骨骼（608 KB）與血管（287 KB）則是打開圖層才下載。
`index.html` 在 `<head>` 就直接發出 manifest 與體表的請求，不然要等 `app.js` 下載解析完才開始抓，
兩段網路白白串在一起。實測（模擬 4 Mbps 行動網路）可用時間 5.96 秒 → **2.2 秒**。

**網格資料先焊接再簡化。** 來源網格沒有共用頂點（13 萬個三角形配到 26 萬個頂點），
既浪費一倍空間，也讓 meshoptimizer 無法跨接縫收邊、簡化到一半就卡住。
先焊接再簡化後，肌肉那包從 1.5 MB 降到 815 KB。

**載入失敗會自動退回內建示意模型。** 解剖資產抓不到或瀏覽器不支援 `DecompressionStream` 時，
`js/body.js` 會用可變半徑 loft 組出一具示意人體，穴位改用原本的骨度座標吸附，功能完全不受影響。

**座標系。** 公尺、y 向上、+z 為身體前方、+x 為受檢者左側（雙側穴位只定義單側，程式自動鏡射）。
真實模型身高 1.73 m；示意模型 1.75 m，主要 landmark：肩 1.415｜肘 1.170｜腕 0.930｜髖 0.928｜
膝 0.520｜踝 0.122｜臍 1.03｜C7 1.45｜頭心 1.63——這組數值是穴位資料的參考框架，改動會讓既有座標失準。

## 重建解剖資產

`data/anatomy/` 已經 commit 進 repo，一般不需要重跑。要重新產生：

```bash
npm install
git clone --depth 1 https://github.com/ashemag/human-atlas /tmp/human-atlas
npm run build:anatomy /tmp/human-atlas/public/models
```

## 資料檢查

改完 `data/` 之後跑一次，會檢查穴位數量、id 重複、肌肉與走行參照、`level`／`lat` 欄位、
神經與血管的穴位／肌肉參照、`data/vessels.js` 與血管網格的 key 是否完全對應、
以及解剖資產與骨架 landmark 是否齊全：

```bash
npm run validate
```

## 免責聲明

本工具僅供解剖與經絡**學習參考**。BodyParts3D 是單一成年男性的參考解剖，不代表所有人的結構與變異；
穴位位置由骨度分寸推算後投影到該模型，是教學等級的近似而非個別化定位。針刺深度為教科書常見參考值，
皆不可作為臨床操作依據；「建議參考穴位」由肌肉交集自動推得，是選穴思路的提示而非治療處方。
**神經層是依解剖描述繪製的示意走行，不是斷層重建**；「鄰近神經／血管」標示的距離由模型幾何算出，
只作數量級參考，實際個體的血管神經位置差異很大，避開血管神經必須靠觸診與臨床判斷。
實際針灸請由合格中醫師執行，運動治療請由合格治療師評估後施行。
